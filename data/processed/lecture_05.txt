Quantitative performance metrics for
LLM Inference
•
Performance metrics for LLM inference
•
Completed requests per minute
•
Time to first token (TTFT): how long before the LLM returns the first token
•
Inter-token latency (ITL): average time between consecutive tokens
•
End-to-end Latency: approximately the same as the average output length of tokens multiplied
by the inter-token latency
•
Cost per typical request: API providers can usually trade off one of the other metrics for cost.
For example, you can reduce latency by running the same model on more GPUs or using higher-
end GPUs.
https://www.anyscale.com/blog/reproducible-performance-metrics-for-llm-inference

TravelPlanner
Are language agents capable of planning in more complex yet realistic settings,
closer to those in which humans operate?
•
Travel planning is a challenging, time-consuming task
•
1,225 user queries along with their reference plans
Findings
•
State-of-the-art LLMs cannot handle complex planning tasks like those in
TravelPlanner. GPT-4 successfully produces a plan that meets all the constraints
for a few tasks (0.6%)
•
Planning strategies such as ReAct and Reflexion are insufficient for the multi-
constraint tasks
•
Common failure modes of existing language agents, such as argument errors in
tool use, being trapped in dead loops, and hallucinations
TravelPlanner: A Benchmark for Real-World Planning with Language Agents

LLMPerf Load Test
•
Spawns a number of concurrent requests to the LLM API and measures the
inter-token latency and generation throughput per request and across
concurrent requests
•
Prompt send with each request
•
The lines are randomly sampled from a collection of lines from Shakespeare sonnets.
•
Tokens are counted using the LlamaTokenizer regardless of which LLM API is being tested.
This is to ensure that the prompts are consistent across different LLM APIs.

=== Page 145 | method=native ===
STAT GR 5293 Sec002 | Spring 2026
LLMPerf Correctness Test
•
Spawns a number of concurrent requests to the LLM API with the following
format:
•
random_number_in_word_format could be for example "one hundred and twenty
three". The test then checks that the response contains that number in digit format
which in this case would be 123.
•
The test does this for a number of randomly generated numbers and reports the
number of responses that contain a mismatch.
